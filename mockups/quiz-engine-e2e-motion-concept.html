Result tallies—count-up, not pop-incounting = accumulation, popping = replacement. Different jobs, both kept

Why tallies count instead of popping: the app already ships animateCount(), and 02-number-pop-in would have been a second idiom for the same job — the shimmer-text problem again. They are not actually the same job: counting climbs through intermediate values and reads as accumulation; pop-in swaps digits and reads as replacement. So tallies count, and pop-in is reserved for values that change to a new value (the live streak, readiness).

Why antalik for loading, not the skeleton: CertAnvil's loader already emits semantic state names — Generating questions…, Verifying quality…, Finalizing… — which is antalik's core doctrine (the label is the state, never "loading"). A pulsing skeleton implies unknown shape and imminent arrival; this pipeline is multi-second and determinate. The skeleton's cross-fade is still the right tool for the arrival, so both are used — each for the half it wins. _root.css is not imported; only one cubic-bezier exists in this file.
