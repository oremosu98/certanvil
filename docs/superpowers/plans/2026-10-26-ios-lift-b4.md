# Lift B4 (Settings on phones) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At phone width the Account tab (`#page-settings`) looks and flows like the approved E2E drawing, every action does what today's does, no browser `confirm()` / `alert()` remains on the phone page, and desktop Settings and `auth-state.js` are untouched.

**Architecture:** A new eager `defer` module `features/ios-settings.js` holds pure model/view pairs and one host that renders into a new `<section id="ios-settings">` (first child of `#page-settings`) plus a new bottom sheet `#ist-sheet`. `features/settings.js` builds the state and hands the host its private actions; the three confirm paths gain opt-in `{confirmed}` / `{skipConfirm}` options. Repaints come from Supabase `onAuthStateChange`, the `renderGauntletDrillsCard` tier chain and the Pass Plan lazy-load callback.

**Tech Stack:** Vanilla JS (IIFE, `window` exports), CSS in `lift-ios.css` (phone only), UAT (`tests/uat/*.js`, vm sandbox via `_fnBody`), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-26-ios-lift-b4-design.md` (approved; review fixes `c991a0ab`). E2E: june-e2e `mockups/cert-ios-settings.html` @ `66c4008a`, states `signed-out`, `free`, `pro`, `exam-date`, `cert-switch`, `diag`, `restore`, `clear-bank`, `delete` (founder approved, 26 Oct).

## Global Constraints

- Phone only (`max-width: 899px`). Desktop Settings renders and behaves as today. **No edits to `auth-state.js`** (gated lane; UAT pins its SHA-256 against `main`).
- `app.js` stays at its 8301-line ratchet; no inline `on*=` in new markup (Sec-P7); one delegated `data-act` listener per host.
- Escape every value from data: email, cert names and codes, backup dates and sizes. Today's Pass Plan HTML passes through (already escaped by its renderer).
- CSS prefix `ist-`. The hide-today rule keys on `#page-settings.ist-on` (a JS-toggled class), never `:has(#ios-settings:not(:empty))`. Plain top padding. Tab bar visible; web top bar hidden while `ist-on`.

## Review Focus

1. **Sign out with unsynced progress:** the phone row only activates `#topbar-signout-link`; it never clears storage itself, so today's upload-before-clear holds. (Task 3 test `Sign out goes through today's handler`.)
2. **Sign-in state arriving after the page drew** (auth resolves late, or sign-out with no reload): the card repaints still, no stale email. (Task 5 test `the card follows a sign-in and a sign-out`.)
3. **A bad file into Import:** a toast, nothing merged, no `alert()`. (Task 4 test `Import: a bad file toasts, a good one asks then merges`.)
4. **Restore and Clear wrong answers on a phone show one ask only**, never a second browser `confirm()`. (Task 4 tests listen for `page.on('dialog')` and fail on any.)
5. **Desktop and the gated file stay put:** desktop Settings markup and behaviour as today; `auth-state.js` byte-identical. (Task 2 desktop test; Task 1 UAT hash.)
