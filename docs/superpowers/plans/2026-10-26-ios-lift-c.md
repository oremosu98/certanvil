# Lift C (first run on phones) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Below 900px a new user meets June's first run: day-0 Home, the 5-question check and its starting point, capped Home, the daily-limit screen and the calm offline state for everyone; the cert picker, lock-in sheet, launch routing and session-restore skeleton behind the onboarding switch. Desktop unchanged.

**Architecture:** A new eager `defer` module `features/ios-firstrun.js` holds the state rules (`placed` / `day0` / `capped`) and pure model/view pairs for every Lift C screen, plus a host for the check (`#ios-check`, a new full-screen section). `features/ios-home.js` asks it which Home to draw. The check drives the existing diagnostic engine through a small exported API and finishes through the onboarding path. The switch-on pieces change `lib/onboarding-firstrun.js`, `lib/onboarding-boot.js` and `lib/router.js` only on their phone path and for the picker bug.

**Tech Stack:** Vanilla JS (IIFE, `window` exports), CSS in `lift-ios.css` (phone only), UAT (`tests/uat/*.js`, vm sandbox via `_fnBody`), Playwright (chromium + mobile-safari, 390/402/1280).

**Spec:** `docs/superpowers/specs/2026-10-26-ios-lift-c-design.md` (approved). E2E: june-e2e `@ ee053395`, HUD "C ›", 11 states (founder approved 26 Oct): `restore`, `free-cert-picker`, `picker-lock`, `picker-pro`, `free-home-day0`, `day0-pro`, `first-run-diag`, `check-score`, `free-capped-home`, `daily-limit`, `offline`.

## Rulings (from the code survey, 26 Oct)

- **Check taken / placed.** `placed(cert) = (history has a non-split row for cert) || (nplus_readiness_snapshots[cert] != null)`. Every quiz also writes a snapshot, so this holds. — Cost if wrong: a returning user without history sees day-0 once.
- **Day-0 skip.** Recorded with today's `nplus_onb_skips` writer (`lib/onboarding-firstrun.js:214`, already cloud-synced per cert). Starting today's 15 records it too. `day0 = !placed && !skipped`.
- **The check stays off the daily 15.** The proxy (`api/ai/generate.js:203`) counts a call when the client sends `_metered: true` (`app.js:4796`). Change that line in place to `_metered: !window._ifrUnmetered` and set the flag only while the check fetches. Gated server files are untouched. — Cost if wrong: two of the free 15 go on the check.
- **Reset clock.** `hoursToReset` = whole hours (rounded up) to the next UTC midnight, the day `consume_daily_quota` counts by. — Cost if wrong: the hint is off by the user's UTC offset.
- **Signed-out users** tapping the check get today's `startDiagnostic` sign-in path (toast + Settings); no new behaviour.
- **Picker bug.** `lib/router.js:74` Free becomes `meta.freeCertId || null` (no subdomain fallback), and `lib/onboarding-boot.js` `gatherProfile` merges local `nplus_freeCertId` and history rows (`activated[cert] = true` when placed). Applies under the switch on any width.

## Review Focus

1. **The check fails mid-fetch** (AI error, offline): back to day-0 with today's AI error card, nothing recorded, flag cleared. (Task 3 test `a failed check fetch leaves day-0 and the meter flag clean`.)
2. **A user quits the app halfway through the check**, then reopens it: day-0 again (no partial snapshot). (Task 3 test `a half check leaves no snapshot`.)
3. **Free user with 0 left taps "Start today's 15" on day-0:** today's quota screen, never a broken quiz. (Task 2 test `day-0 with nothing left goes to the quota screen`.)
4. **Going offline mid-quiz:** only the small Offline bar shows; the quiz is not replaced. (Task 5 test `offline during a quiz shows the bar only`.)
5. **Rotating or resizing across 899px** on day-0, the check or the daily limit: desktop gets today's screens, no stuck `ifr-*` class. (Tasks 2–5 each pin one crossing.)
